# إغلاق ثغرة الكتابة بالمفتاح العام

## الوضع المؤكد (17 نوفمبر 2026)

`scripts/probe_anon_writes.mjs` بيثبت إن `sb_publishable_...` (المفتاح اللي بيتوزّع مع كل نسخة من التطبيق)
بيقدر يعمل insert / update / delete على الجداول الأربعة. عن طريقه اتكتبت تصنيفات زبالة
(`test`, `New Vategory`, اسم فاضي) هي اللي كانت بتوقف تحميل أول مرة.

## إيه اللي أنا عملته بالفعل

- شلت (soft delete) التصنيفات الزبالة، والمكتبة الحية بقت 5 تصنيفات حقيقية.
- التطبيق بقى بيتخطى أي صف السكيما بترفضه بدل ما يوقف التحميل كله.
- التطبيق بقى بيطلب المفتاح صريح، ومفيش تحميل "ناجح" بمفتاح فاضي.

## إيه اللي محتاج تشغيله إنت (٣ دقايق)

### ١. شغّل سكربت الإغلاق

Supabase dashboard → **SQL Editor** → افتح `supabase_production_lock_read_only.sql` → **Run**.

المفروض الترن يرجع تقرير فيه `anon_read = true` و `anon_write = false` لكل جدول.
لو رجع خطأ بخصوص policy، القسم رقم ٤ في الملف بيقولك اسم الـpolicy اللي محتاجة مراجعة قبل ما يكمل.

### ٢. تأكد بنفسك

```bash
node scripts/probe_anon_writes.mjs
```

المتوقع: كل عمود كتابة يرجع 401/403، والـread 200، والسطر الأخير:
`The public key is read-only on all four content tables.`

### ٣. اتأكد إن لوحة الإدارة شغالة للحساب الأدمن

1. افتح التطبيق → اضغط ١٠ مرات على عنوان «دليل المحاماة» → دخول الأدمن.
2. أضف تصنيف تجريبي، وامسحه. لو الشغلتين نجحوا، الحساب بيكتب بالجلسة بتاعته وليس بالمفتاح العام.
   بعدها امسح التصنيف التجريبي نهائيًا من مكانه.

## بدائل لو الـstep ٣ اتكسر

| الحل | متى تختاره | الحل الـ"صح" |
|---|---|---|
| تعديل أي صف مباشرةً من SQL Editor | بس المستخدمين بيكتبوا كتير | Service role يكتب الـrows |
| إضافة `AFTER INSERT/UPDATE/DELETE` على الجداول تكتب في جدول outbox دائم، وSQL job (pg_cron) يطبقه | أنت محتاج تحديث فوري | لا يوجد قفل على anon |

المهم إن `anon` يفضل للقراءة بس. ده مش اختياري: أي مفتاح بيتوزع مع تطبيق موبايل مكشوف، والتحكم الحقيقي في المكان اللي بيسمح له بالقراءة فقط.
